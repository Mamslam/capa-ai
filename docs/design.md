## Problem Statement

EU pharmaceutical SMEs (50–200 employees) spend enormous QA staff time writing
Corrective and Preventive Action (CAPA) reports — a mandatory EU-GMP compliance
document triggered every time a deviation, complaint, or audit finding occurs.
QA managers write 5–20 CAPAs per month. Each one is formulaic, repetitive, and
time-consuming. Legacy QMS software (Veeva, MasterControl) is enterprise-only and
costs $25K+/year. Qualio exists at the SMB level but has no AI. Nobody has built
an AI-native compliance documentation tool for the EU pharma SME segment.

## Status Quo

EU pharma QA managers currently:
1. Open a Word document template (usually copied from the previous CAPA)
2. Manually fill in: deviation description, immediate action, root cause analysis,
   corrective action, preventive action, effectiveness check criteria, timeline
3. Submit for review (typically 2–3 review cycles with QA Director)
4. File in SharePoint or a legacy QMS that doesn't help draft — just stores

Pain: repetitive, easy to miss required fields, inconsistent format across QA team,
audit findings often cite poor CAPA quality. No automation exists.

---

## Target User & Narrowest Wedge

**Target user:**
- Title: QA Manager or QA Specialist at a 50–200 employee EU pharma company
- Context: company has EU-GMP certification (or is pursuing it), runs 5–50 CAPAs/month
- Pain: spends 2–4 hours per CAPA on writing, is the bottleneck for closure
- Gains: faster CAPA closure = fewer open findings at inspection = less stress

**Narrowest wedge:**
A single-purpose web tool that takes:
- Input: deviation description (free text) + root cause category (dropdown)
- Output: draft CAPA report as a .docx download following EU-GMP Part I
  Chapter 8 format (Chapter 8 covers quality defects and product recall
  handling; CAPAs are the mandated corrective mechanism).

  Required output fields:
  1. Deviation / nonconformance description
  2. Immediate action taken
  3. Root cause analysis (5 Whys or Ishikawa method)
  4. Corrective action (what, who, by when)
  5. Preventive action (systemic change)
  6. Effectiveness check criteria + verification date
  7. Responsible person + QA reviewer name
  8. Target closure date

The QA manager still reviews, edits, and signs. The AI drafts. The tool saves
60–90 minutes per CAPA. At 10 CAPAs/month, that's 10–15 hours of QA time
recovered — immediately visible, easily quantifiable ROI.

---

## Constraints

- Must work alongside existing QMS (not replace it) — output is a document,
  not a system
- Regulatory: AI-generated draft must be clearly labeled "DRAFT — requires QA
  review and sign-off" to avoid EU-GMP validation concerns
- **Stateless by design (MVP):** The tool generates and serves a .docx download.
  No CAPA content is stored server-side. This eliminates GDPR data residency
  concerns and removes the need for EU pharma computer system validation (CSV)
  of the tool itself. Client files the .docx in their own QMS.
- Export format: .docx (Microsoft Word). EU QA managers file in SharePoint or
  their QMS — Word is the universal format they already use.
- Data sensitivity: no patient data involved in CAPAs (process deviations only),
  reducing GDPR complexity significantly
- Distribution: pharma QA professional networks (LinkedIn pharma QA groups,
  ISPE France/Germany chapters), NOT generic SaaS channels
- Operator constraint: must build alongside CGI employment without conflict of
  interest — initial version is an open/public tool or tested only with
  non-CGI contacts

## Premises

1. Pharma QA managers will trust AI-drafted CAPA text as a starting point,
   as long as (a) it's labeled DRAFT, (b) they review it, and (c) it correctly
   follows the EU-GMP format they already know. This needs validation.

2. The EU pharma SME segment (50–200 employees) is the right entry point.
   Large pharma has Veeva. Small pharma can't afford or maintain complex systems.

3. Distribution runs through pharma QA professional communities — NOT Google Ads.
   The first 10 users come from the CGI network and ISPE chapter contacts.

4. The MVP is one document type (CAPA), not a full QMS. Scope is deliberately
   narrow to validate the core assumption before expanding.

5. The 15-year ERP background is the moat. Anyone can call the Claude API.
   Not anyone knows what "EU-GMP Annex 15" means or what inspectors actually ask for.

## Approaches Considered

### Approach A: CAPA AI — Single Document MVP [CHOSEN]
  Summary: AI tool that drafts CAPA reports from deviation input + root cause.
  Output follows EU-GMP format. Validate with 5 QA managers before coding.
  Effort: S (2–4 weeks to first version)
  Risk: Low
  Pros:
    - CAPA is the most painful, most frequent compliance doc in pharma QA
    - Validates the trust assumption before building a full QMS
    - Can be shown to CGI pharma contacts as an internal tool test
  Cons:
    - Single doc type — narrow initial revenue ceiling
    - Qualio or a well-funded startup could copy once proven
  Reuses: Claude API (already integrated in HalalCRM), Railway + Vercel stack

### Approach B: Full AI QMS Layer
  Summary: Multi-tenant SaaS covering deviations, CAPAs, audit prep, SOP drafting.
  Effort: XL (3–6 months)
  Risk: Medium — builds before validation
  Pros: Full workflow capture, higher switching cost, recurring revenue
  Cons: Regulatory complexity, conservative buyers, over-built before validated

### Approach C: Inspection Prep AI (Event-Driven Premium)
  Summary: One-time purchase per EU-GMP inspection. €3,000–8,000 per prep package.
  Effort: M (4–6 weeks)
  Risk: Medium — lumpy revenue, need to be known before inspection is announced
  Pros: Extremely high willingness to pay, clear ROI
  Cons: Event-triggered sales, hard to predict, requires community presence

deviation tracking, audit prep, and SOP drafting are all the same underlying
pattern (domain input → AI-drafted EU-GMP format document).
