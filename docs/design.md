## Problem Statement

EU pharmaceutical SMEs (50–200 employees) spend enormous QA staff time writing
Corrective and Preventive Action (CAPA) reports — a mandatory EU-GMP compliance
document triggered every time a deviation, complaint, or audit finding occurs.
QA managers write 5–20 CAPAs per month. Each one is formulaic, repetitive, and
time-consuming. Legacy QMS software (Veeva, MasterControl) is enterprise-only and
costs $25K+/year. Qualio exists at the SMB level but has no AI. Nobody has built
an AI-native compliance documentation tool for the EU pharma SME segment.

## Status Quo

EU pharma QA managers currently:
1. Open a Word document template (usually copied from the previous CAPA)
2. Manually fill in: deviation description, immediate action, root cause analysis,
   corrective action, preventive action, effectiveness check criteria, timeline
3. Submit for review (typically 2–3 review cycles with QA Director)
4. File in SharePoint or a legacy QMS that doesn't help draft — just stores

Pain: repetitive, easy to miss required fields, inconsistent format across QA team,
audit findings often cite poor CAPA quality. No automation exists.

## Target User & Narrowest Wedge

**Target user:**
- Title: QA Manager or QA Specialist at a 50–200 employee EU pharma company
- Context: company has EU-GMP certification (or is pursuing it), runs 5–50 CAPAs/month
- Pain: spends 2–4 hours per CAPA on writing, is the bottleneck for closure
- Gains: faster CAPA closure = fewer open findings at inspection = less stress

**Narrowest wedge:**
A single-purpose web tool that takes:
- Input:
    1. Deviation description (free text) — what happened
    2. Root cause category (dropdown — exactly 5 options):
       - Equipment: machine, instrument, calibration, or maintenance failure
       - Process: procedure not followed, procedure unclear, or process gap
       - People: training gap, human error, or communication failure
       - Materials: supplier issue, wrong material, or specification mismatch
       - Environment: facility, contamination, or environmental condition
    3. Immediate action taken (optional free text)

- Output: draft CAPA report as a .docx download following EU-GMP Part I
  Chapter 8 format (Chapter 8 covers quality defects and product recall
  handling; CAPAs are the mandated corrective mechanism).

  Required output fields:
  1. Deviation / nonconformance description (AI-generated prose from input)
  2. Immediate action taken (AI-generated; uses field 3 input if provided)
  3. Root cause analysis (5 Whys structured list — AI-generated)
  4. Corrective action (what, who, by when — AI-generated; "who" and "by when"
     are placeholders the QA manager fills in)
  5. Preventive action (systemic change — must differ from corrective action;
     AI is prompted to enforce this)
  6. Effectiveness check criteria (AI-generated prose) + verification date
     (placeholder: "[QA to enter date]" — user fills in, not AI-generated)
  7. Responsible person + QA reviewer name (placeholders — user fills in)
  8. Target closure date (placeholder — user fills in)

The QA manager still reviews, edits, and signs. The AI drafts. The tool saves
60–90 minutes per CAPA. At 10 CAPAs/month, that's 10–15 hours of QA time
recovered — immediately visible, easily quantifiable ROI.

## Constraints

- Must work alongside existing QMS (not replace it) — output is a document,
  not a system
- Regulatory: AI-generated draft must carry "DRAFT — requires QA review and
  sign-off" in the document header on every page. This label is present at
  generation time; it is not technically locked (the .docx is editable in Word).
  The QA manager's review obligation — not a technical lock — is what enforces it.
  This is identical to how Word templates work today. Never omit it at generation.
- **Stateless by design (MVP):** The tool generates and serves a .docx download.
  No CAPA content is stored server-side. This eliminates GDPR data residency
  concerns and removes the need for EU pharma computer system validation (CSV)
  of the tool itself. Client files the .docx in their own QMS.
- **Freemium enforcement (client-side):** The 10-free-CAPA limit is tracked via
  localStorage in the browser. No server state required — consistent with
  stateless design. Savvy users can reset by clearing browser storage; this is
  acceptable at MVP (the free tier is for discovery, not strict gatekeeping).
  On generation attempt 11+, show upgrade prompt. No account required to use
  free tier; account required to upgrade to Pro.
- **Error handling:** If the Claude API returns a malformed or truncated response,
  retry once automatically. If the retry fails, return a user-facing error:
  "Generation failed — please try again." Do not surface API error details.
  Do not partially write the .docx.
- **Rate limiting:** IP-based, 10 generation requests per hour per IP. Applies
  to free tier only. Pro subscribers (authenticated) are unlimited. Prevents
  automated abuse of the free tier without requiring accounts.
- Export format: .docx (Microsoft Word). EU QA managers file in SharePoint or
  their QMS — Word is the universal format they already use.
- Data sensitivity: deviation descriptions are process data (temperature, equipment,
  procedure), not patient data. GDPR sensitivity is low. One UI note prevents
  the edge case: "Do not include operator names, patient information, or batch
  numbers in your description."
- Distribution: pharma QA professional networks (LinkedIn pharma QA groups,
  ISPE France/Germany chapters), NOT generic SaaS channels
- Operator constraint: must build alongside CGI employment without conflict of
  interest — initial version is an open/public tool or tested only with
  non-CGI contacts

## Data Security & Compliance Architecture

### GDPR

Data flow: pharma company (controller) → CAPA AI (processor) → Anthropic (sub-processor)

Required actions before launch:
1. Sign Anthropic's DPA (covers EU SCCs for US data transfer). Available at
   anthropic.com/legal/dpa. One form.
2. Prepare a 1–2 page customer DPA: "We process your CAPA data only to generate
   the requested document. We retain nothing. We use Anthropic as a sub-processor
   under EU Standard Contractual Clauses."
3. Add to UI: "Do not include patient names, batch numbers, or operator names in
   your deviation description."
4. In Terms of Service: disclose Anthropic as sub-processor, note their default
   30-day prompt retention for safety review, state that Business plan customers
   can request zero-retention if required.

### EU-GMP Annex 11 / Computer System Validation (CSV)

CAPA AI does NOT require Annex 11 validation. The argument:

Annex 11 applies to computerised systems that create, process, or maintain GMP
records. CAPA AI does not create a GMP record — it generates a draft document.
The GMP record is the signed CAPA stored in the customer's QMS after the QA
manager reviews, edits, and approves it.

The Word parallel: QA managers today draft CAPAs in Microsoft Word. Word is not
Annex 11 validated. CAPA AI is a better Word template — it still requires human
review and sign-off before anything enters the QMS.

The DRAFT label is the technical mechanism that enforces this distinction. It must
appear on every generated document and cannot be removed by the user.

Watch list: EMA may issue specific guidance on AI-assisted QA documentation in
2026–2027. Track EMA digital guidance releases and update Terms of Service if needed.

## Premises

1. Pharma QA managers will trust AI-drafted CAPA text as a starting point,
   as long as (a) it's labeled DRAFT, (b) they review it, and (c) it correctly
   follows the EU-GMP format they already know. This needs validation.
   Annex 11 CSV is not required because CAPA AI is a drafting tool, not a GMP
   system — same as Word. The DRAFT label is the technical enforcement of this
   distinction.

2. The EU pharma SME segment (50–200 employees) is the right entry point.
   Large pharma has Veeva. Small pharma can't afford or maintain complex systems.

3. Distribution runs through pharma QA professional communities — NOT Google Ads.
   The first 10 users come from the CGI network and ISPE chapter contacts.

4. The MVP is one document type (CAPA), not a full QMS. Scope is deliberately
   narrow to validate the core assumption before expanding.

5. The 15-year ERP background is the moat. Anyone can call the Claude API.
   Not anyone knows what "EU-GMP Annex 15" means or what inspectors actually ask for.

## AI Architecture

### How pharma knowledge enters the system

Claude has general EU-GMP knowledge from training. The gap is format precision
and inspection-level detail — what an inspector actually rejects, not just what
the regulation says. That knowledge lives in the system prompt, not the model.

**System prompt = the domain expert**
The system prompt encodes Mamadou's 15-year pharma knowledge once:
- Exact 8-field EU-GMP Part I Chapter 8 CAPA structure
- What inspectors look for in each field (e.g., 5 Whys must trace to a systemic
  cause, not an individual; preventive action must differ from corrective action)
- Common QA mistakes that generate audit findings
- Regulatory register: active voice, measurable outcomes, no hedging
- Root cause guidance per dropdown category (Equipment / Process / People /
  Materials / Environment)

This is the moat. Anyone can call the Claude API with "draft a CAPA for: {input}".
Not anyone knows what an EU-GMP inspector will flag as a weak corrective action.

**Prompt caching = affordable at scale**
The system prompt will be 2,000–5,000 tokens of pharma knowledge. With Anthropic's
prompt caching, it is processed once and cached. Subsequent generations within the
5-minute cache window reuse it at ~10% of the normal token cost.
Cost model caveat: at MVP volume (10 CAPAs/month per customer ≈ one every 3 days),
the cache will almost never be warm. Budget for cache-cold pricing in the MVP phase.
Caching becomes materially cost-saving post-launch when multiple customers generate
CAPAs within the same time window. Use prompt caching from day 1 anyway — it is
one configuration flag and costs nothing when cold.

**Structured user input = specific context**
Two required fields give Claude enough to generate a complete draft:
1. Deviation description (free text) — what happened
2. Root cause category (dropdown) — which lens to apply

Optional: immediate action already taken. This is sufficient context for
field-by-field generation without needing batch records, SOPs, or process data.
The QA manager's review catches any field that needs company-specific detail.

**Not needed for MVP:**
- Files API (useful v2: upload company SOPs as additional context)
- RAG / vector search (useful v3: company-specific document libraries)
- Fine-tuning (not available for Claude; not needed with good system prompting)

**First build task:** Write and test the system prompt before writing any
application code. Generate 5 sample CAPAs from minimal inputs and show them to
one QA manager. If they say "this would save me 90 minutes," build. If they say
"I'd rewrite all of this," fix the prompt first.
